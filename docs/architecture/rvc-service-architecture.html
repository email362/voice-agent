Architecture proposal before implementation

Separate local RVC conversion service for agent TTS audio.

Create rvc-service/ as an isolated Python/FastAPI app. It discovers the existing model files in the project root, exposes GET /health and POST /convert, and can be wired into the Node/Fastify Deepgram proxy through RVC_SERVICE_URL.

Proposed service flow

Recommended approach

Use FastAPI wrapper around rvc-python

This uses an existing RVC inference package instead of hand-rolling inference. The rvc-python README documents CLI usage, RVCInference module usage, API mode, CPU/GPU support, and model directories with .pth plus optional .index.

Endpoint contract
  • GET /health: model/index discovery, backend import availability, device, loaded status.
  • POST /convert: accepts multipart/form-data file field named audio, returns audio/wav.
  • Optional query params: pitch, index_rate, f0_method. Default device is cuda:0.

Smoke checks

Tests prove model discovery, health payload, missing-backend behavior, and endpoint validation without requiring live Deepgram.

Runtime note

CUDA will be the default target: RVC_DEVICE=cuda:0. If CUDA is unavailable, the service falls back to cpu and reports the latency tradeoff in /health.
