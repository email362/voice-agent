Implementation tasks

Add mic-live cue and gate microphone frames

  • Add a pill-style Mic idle / warming up / live / streaming indicator near the Start and Stop buttons.
  • Add canStreamMic and browser-side audio counters.
  • Only call socket.send(pcm) after SettingsApplied.
  • Set the visual cue to Mic live at readiness and Mic streaming once frames leave the browser.
  • Expose a temporary UI status with frame and KB counts.

Cancel playback on UserStartedSpeaking

  • Track active audio buffer source nodes.
  • Stop and clear playback when Deepgram detects the user speaking.
  • Reset queued playback time to the current audio context time.

Add opt-in proxy diagnostics in server.js

  • Use DEBUG_AUDIO=1 to avoid noisy default logs.
  • Aggregate client binary frame and byte counts every two seconds.
  • Log client and Deepgram JSON event types, including warning/error codes.

Verify with live audio evidence

  • Run syntax checks for client and server files.
  • Start with DEBUG_AUDIO=1 npm start.
  • Confirm the visual mic cue, UI counters, server byte counters, UserStartedSpeaking, and user ConversationText.

Failure interpretation

Browser layer

If the UI frame counter stays at zero, focus on microphone permission, input device selection, audio context state, or whether onaudioprocess is firing.

Proxy layer

If UI counters rise but server counters do not, the browser is not sending binary frames over the WebSocket path we expect.

Deepgram layer

If server counters rise but Deepgram emits no user events, inspect USER_AUDIO_FORMAT, ASR_DRIVER_TIMEOUT, and listen model settings.

Known tradeoff

ScriptProcessorNode is deprecated. This plan keeps it to avoid a larger audio pipeline rewrite while we isolate the current failure.
